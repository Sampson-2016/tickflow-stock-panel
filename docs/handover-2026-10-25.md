## 2. R1 — Mock 双接口（批量回填 + 流式增量）

### 2.1 需求陈述

用户选择某个起始时间（如 10:00）开启 mock 时，9:15–10:00 这段不能是空的。后端必须：

1. 一次性生成 9:15 到起始时间的全部历史 tick（**批量回填**）。
2. 然后按配置间隔逐个推送增量 tick（**流式**）。
3. 两阶段无缝衔接，时间轴无间隙、无重叠。

### 2.2 设计要点

- **接口拆分**：mock 不再是单一循环，而是 `MockProvider.backfill(...)` + 流式推送两个独立阶段。
- **共用标的列表**：mock 与真实循环共用同一标的列表，由「测试页 mock 落盘」「测试页 real 落盘」「超买超卖」三个模块的开关统一控制，**无需在每个模块重复填写标的**。
- **时间口径**：所有时间戳必须使用 `app/markets.py` 的 `CN_TZ = timezone(timedelta(hours=8))`，禁止用 `datetime.now()`（naive）。
- **失败处理**：backfill 阶段失败应 fail-closed，不进入流式阶段；流式阶段单个 tick 推送失败不影响后续。

### 2.3 关键契约

- `MockProvider.backfill(symbols: list[str], from_dt: datetime, to_dt: datetime) -> list[Tick]` — 一次性返回 `[from_dt, to_dt]` 区间内所有 tick。
- 流式接口按 `scheduler.py` 的配置间隔推送增量 tick，与 backfill 阶段返回的最后一个 tick 严格递增。

### 2.4 进度

- [x] `MockProvider.backfill` 已实现
- [x] scheduler 已接入 backfill → 流式衔接
- [x] 用户切起始时间时无空段

## 4. R3 — EChartsIntraday 时间轴 `NaN:NaN` 渲染修复

### 4.1 需求陈述

分时图 x 轴时间 formatter 渲染出 `NaN:NaN`，肉眼可见但不影响数据。

### 4.2 设计要点

- **根因**：category 轴 formatter 在边界 tick（特别是只有一个 tick）上无法正确解析时间字段。
- **解决**：改用 `time` 类型时间轴，formatter 收到的是 timestamp（毫秒），用 `new Date(value)` 解析后格式化为 `HH:mm`。
- **副作用**：time 轴自动按时间间隔排布单个 tick，避免「单个 tick 被拉满到 x 轴末端」的旧问题。

### 4.3 关键约束（来自项目记忆）

> 直接修改 echarts category 轴的 `connectNulls`、`areaStyle` 等属性无法解决「单个 tick 被拉满到 x 轴末端」的问题，必须改用 `time` 类型时间轴才能正确定位单个 tick 的位置。

### 4.4 进度

- [x] 时间轴改为 `type: 'time'`
- [x] formatter 收到 timestamp 后正确格式化
- [x] 不再出现 `NaN:NaN`

## 5. R4 — 清空落盘按钮真正清空

### 5.1 需求陈述

点击「清空 mock 落盘」和「清空 real 落盘」后，页面上的 tick 计数没有变 0，分时图也没刷新。需要：

1. 后端真的清空对应类型的落盘数据。
2. 前端 tick 计数和分时图同步更新为清空状态。

### 5.2 设计要点

- **后端**：`store.py` 的清空方法必须同时：
  - 删除对应类型的落盘文件（mock / real 各自独立）。
  - 清零 tick 计数与状态字段（内存态 + 持久化态）。
- **前端**：清空成功后必须 `queryClient.invalidateQueries(...)` 对应查询键，使分时图立即重新拉取（得到空数据 → 立即重绘）。
- **缓存失效范围**：精确失效 `mock` 或 `real` 的查询键，不要无条件清空所有 free_realtime 查询。

### 5.3 关键端点

- `POST /api/free-realtime/prune` — 入参 `kind: "mock" | "real"`，分别清空对应类型。

### 5.4 进度

- [x] 后端按 kind 独立清空落盘文件 + 计数
- [x] 前端精确失效对应查询键，分时图立即重绘

## 10. R9 — 超买超卖阈值改为单股配置；删除全局阈值；加单股启动开关

### 10.1 需求陈述

原超买超卖阈值是基于全局统一配置的（偏离 5 日线百分比一个值管所有股票）。需求：

1. **删除全局超买超卖阈值配置**。
2. **改为基于单个股票的独立阈值配置**：每只股票有自己的 overbought_pct / oversold_pct。
3. **加单股启动开关**：每只股票可独立启停超买超卖监控，而不是全局开或关。

### 10.2 设计要点

- **配置 schema**：`services/free_realtime/config.py` 增加「单股阈值 + 单股开关」结构，不再读全局阈值字段。
- **后端接口**（已落地于 `custom/free_realtime_ext.py`）：
  - `GET /api/free-realtime/overbought-oversold/symbols` — 列出已配置的单股阈值
  - `POST /api/free-realtime/overbought-oversold/symbols` — 新增单股配置
  - `DELETE /api/free-realtime/overbought-oversold/symbols/{symbol}` — 删除单股配置
  - `PUT /api/free-realtime/overbought-oversold/symbols/{symbol}` — 更新单股开关
  - `PUT /api/free-realtime/overbought-oversold/symbols/{symbol}/thresholds` — 更新单股阈值
- **评估逻辑**：`services/free_realtime/overbought_oversold.py` 的 `evaluate(...)` 必须按 symbol 查其独立阈值；未配置阈值的标的直接跳过，不再用全局兜底值。
- **前端**：`OverboughtOversoldPage.tsx` 新增单股阈值编辑器（per-symbol 输入 overbought_pct / oversold_pct + 启停开关），移除全局阈值输入框。

### 10.3 关键约束（来自项目记忆）

> 超买超卖功能的阈值配置需基于单个股票独立设置，不再使用全局统一阈值配置。

## 12. 关键约束与禁区

### 12.1 必须遵守

- **时区**：所有交易时段判断使用 `app/markets.py` 的 `CN_TZ`，禁止用 naive `datetime.now()`。
- **复用**：分时图统一用 `StockIntradayChart`，不在多个页面平行实现。
- **共用标的**：mock 与 real 循环共用同一标的列表，由三个模块的开关决定，不在多个地方重复填写。
- **数据契约**：`change_pct` / `turnover_rate` 在不同层有不同口径（小数 vs 百分数），跨边界必须显式转换，禁止「<1 就 ×100」启发式。
- **清空失效范围**：精确失效 mock 或 real 查询键，不无条件清空所有 free_realtime 查询。

### 12.2 禁止

- 禁止继承 `StrategyEngine` / `BacktestEngine` / `ScreenerService` / `StrategyMonitorService` / `DataStore` 等大型核心类。
- 禁止绕过 `app/data_providers/` 抽象直接在策略 / 监控 / API / 前端里硬编码数据源调用。
- 禁止在条件块内调用 React Hooks（必须提升到组件顶层，避免 hook 调用顺序错乱）。
- 禁止直接修改 echarts category 轴的 `connectNulls` / `areaStyle` 来修复单个 tick 拉满问题（必须用 `time` 类型时间轴）。
- 禁止用「数值小于 1 就乘 100」启发式转换 `change_pct`（会掩盖真实数据错误）。
